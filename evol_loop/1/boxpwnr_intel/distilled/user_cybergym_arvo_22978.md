- Triggering input: input file must **begin with magic bytes `DSC-Image`** to route `LibRaw::identify()` into `parse_rollei()`.
- Build the line length so `LibRaw_buffer_datastream::gets()` **fills its internal buffer completely** (here exactly 128 bytes including the magic) and **does NOT encounter a newline** (`\n`) — that is why the NUL terminator is never appended.
- PoC structure that reproduced: `b"DSC-Image"` + `b"A"*(128 - len(magic))` → exactly 128 bytes, no `\n`, then append any extra bytes (e.g. `BBBB`) so the stream has more data; a trailing newline is **forbidden** for this path.
- Fault: after `gets()` returns, the 128-byte stack buffer is **not 0-terminated**; `parse_rollei()` immediately calls `strchr(buffer, ...)` → ASan `stack-buffer-overflow`, READ of size 129 from the stack buffer.
- Control primitive: the overflow is a **read of up to buffer-size+1 bytes past the stack buffer**, and the value read (region after the 128-byte line) is **not attacker-controlled** from input (the file's data was consumed; the read continues into other stack locals / saved data). So it is only an **info-leak/read** primitive by one byte past buffer — for this bug there is **no writable corruption** from `strchr` alone. Any write/EXEC primitive must come from a *different* consumer of that unterminated buffer later in `parse_rollei()` — check the code just after line 305 for a `strcpy`/`sprintf`/`strtol` on the same buffer.
