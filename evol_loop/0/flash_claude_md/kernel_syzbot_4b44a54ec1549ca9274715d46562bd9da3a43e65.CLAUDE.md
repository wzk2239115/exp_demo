## Verified recon facts
- Target kernel is ~6.6 with `CONFIG_INIT_ON_ALLOC_DEFAULT_ON=y`; SLUB allocator with no freelist randomization.
- `/proc/kallsyms` is world-readable but addresses are masked (KASLR active). Kernel base often decodable from known symbol offsets if KASLR is off locally.

- Build is an initramfs (gzip cpio). `/home/user/chal` is a bash script that boots into nsjail; sandbox lacks userfaultfd (EPERM) and static busybox applets like `mkdir`.

## Anti-patterns to avoid
- **QEMU boot timeout or "Attempted to kill init" panic**: this is a kernel cmdline ordering issue—`nokaslr` must appear *before* `init=`. If you hit this, reorder cmdline args, do not chase other boot causes.
- **Same file-upload mechanism failing repeatedly (heredoc floods, FAT mount permission errors)**: switch to HTTP server on host + `wget` in guest; this was the only reliable channel.
- **Long-running guest programs producing no output then hanging**: add a watchdog/log per iteration and run small batches (10) first; a 300-iter run can deadlock while small runs pass—diagnose with the small run before scaling.
- **Repeatedly editing `vm_test.py` harness sentinels instead of the exploit**: if a test harness needs >3 fixes, rewrite it from scratch; framework debugging is a time sink.
- **Continuing source analysis after a confirmed runtime heap fact**: when a slab-size/cache-merging fact is verified, immediately re-evaluate your heap strategy; do not keep reading struct layouts.
