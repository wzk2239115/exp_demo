## Verified recon facts
- `WasmDispatchTable` extends `TrustedObject`; `kHeaderSize` matches `ExposedTrustedObject` in no-sandbox builds. Entries written at `entry_index * 16`.
- `ProtectedFixedArray::New` fills slots with `Smi(0)`; for non-funcref (e.g. arrayref) tables, no dispatch table initialization occurs, so slots stay `Smi(0)`.
- `dispatch_tables` uses trusted-space compression (`TrustedSpaceCompressionScheme`); builds have pointer compression on, sandbox off, `is_debug=false` (no DCHECK).
- `%CountUnoptimizedWasmToJSWrapper` works with `--allow-natives-syntax` and reliably reports tier-up triggering (count decreases).
- Key build flags: `V8_COMPRESS_POINTERS`, `V8_STATIC_ROOTS`; static roots put `undefined` at a known small offset (e.g. compressed 0x61) near cage base.
- Direct `Smi(0)->length()` read resolves to address 3 and segfaults; confirmed via a tiny C program.
## Anti-patterns to avoid
- **PoC runs in release and doesn't crash**: Don't keep re-running variants expecting a crash — switch to static/binary analysis to find what gates the vulnerable path.
- **Script construction with `head`/`tail` repeatedly yields SyntaxError**: Read the downloaded builder file's end first, then append test code in one piece; reformulate the query instead of re-cutting.
- **Online issue/commit search returns empty/404 for many steps**: if 3 different endpoints fail, stop fetching; analyze the downloaded revision diff or local source instead.
- **Auditing the same write path (`WasmDispatchTable::Grow`) many times with same "no path" conclusion**: stop and compile an explicit list of ruled-out paths before revisiting.
- **Assuming the bug is a memory-corruption primitive just because source suggests it**: verify behavior against the actual binary's disassembly early; machine code wins over source interpretation.
## Missed signals
- If you find a description stating the bug "crashes with DCHECK" only, treat the release build as likely NOP for that exact path — pivot to asking how a different slot value (not `Smi(0)`) could reach the vulnerable loop, before deep-diving further.
- If you find static roots offsets (like `undefined` at a near-cage-base compressed address), act on them immediately as potential fake-object anchors; don't defer integrating them into an exploit plan.
- If you confirm no crash on `/challenge/d8`, that's a strong signal the intended path needs a controlled non-zero dispatch-table slot — check which objects you can place there first.
