# Prior-run notes for v8_human_401732698_report.md

## Verified recon facts
- Challenge d8 has no `print` / `printErr` / `read` / `write` globals; only `console.log` works for output.
- No `Sandbox` API, no `--allow-natives-syntax`, no `%` intrinsics, no `--sandbox-fuzzing` (readonly flag, errors out).
- Remote server runs same hardened d8: `/challenge/d8 "$tempfile"`, no flag overrides accepted.
- Build: `v8_enable_sandbox=true`, pointer compression on, Turbofan off by default (`--turbolev`), Maglev on by default, Turbofan at 3000 invocations.
- `catflag` is a static non-PIE ELF at `/challenge/catflag`; you run as `nobody` (uid/gid 65534) via nsjail.
- GDB useless: ptrace blocked entirely, including as root (seccomp/restriction).
- Source at `/src/v8` is a shallow clone (no useful git history); upstream patches fetched via gitiles work but GitHub API rate-limits to ~50 req/hr.
- Standard globals include only `d8.files` helpers and `d8.serializer.{serialize,deserialize}` — nothing exploitable exposed.
- Worker serialization uses the standard shell ValueSerializer, not a custom one.

## Anti-patterns to avoid
- **Repeatedly re-confirming Sandbox API absence after first proof**: after steps ~7/48, don't re-test `typeof Sandbox`; it's closed.
- **Spending >10 steps on source paths only reachable via debug-evaluate**: if a path requires `PRIVATE_NAMES_ONLY` or debug contexts, it's a dead end for remote; switch technique early.
- **Forcing a JIT tier via flag gymnastics (try/catch, eval, generators) with no signal**: if natural warmup doesn't trigger after 2-3 variants, stop and change the code shape, not the flags.
- **Repeating the same stale-read pattern with `bad=0` output >3 times**: the loop didn't fire; reformulate the corrupted access target before another run.
- **Fetching upstream code diffs blindly**: read the downloaded diff file once and trace it into the local tree before spawning the next search; the issue tracker requires login (don't retry issues.chromium.org).
- **Re-attempting GDB after first ptrace denial**: one confirmation is enough, even as root.

## Missed signals
- **If a JIT bug fires in one compiler mode but not default, check OSR specifically**: in the prior run, one bug only fired after a loop OSR-compiled to Turbofan; natural warmup missed it, but the loop path was the trigger.
- **Observed `arr[42]` returns undefined due to bounds check — don't assume the only OOB read vector; consider indirect indexing** instead of persistent retries with the same direct access.
- **If LSE handles a named property as `JSSetNamedProperty` not `StoreField`, the field-kill model is different**: treat this as a fork point and inspect that path specifically, not the generic store path.
- **A stale value that fires repeatedly (not just once) is a stronger primitive than one-off; verify whether the stale length is also affected** before concluding the primitive can't scale.

## Environment notes
- VM boots with restrictive seccomp: no ptrace, no cores; use `d8_copy` (a cp of the binary) for `strings`/symbols since the original has an SGID bit that breaks tooling.
- Rootfs extraction: workspace at `/workspace` is writable; `/src/v8` is read-only except for build artifacts.
- Network: gitiles/chromium.googlesource works, GitHub API rate-limited, issues.chromium.org requires login; use `curl` with a prefix-strip (`)]}'\n`) for JSON logs.
- `--no-maglev` is a valid flag and changes tier thresholds; useful for isolating compiler-specific behavior.
- A copy of the binary with symbols exists (`d8_copy`) — use it for `nm`/`objdump` instead of the stripped original.
