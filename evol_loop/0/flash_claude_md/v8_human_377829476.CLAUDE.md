## Anti-patterns to avoid
- **Repeatedly trying `--print-code` / `--print-opt-code` and getting `Contradictory value for readonly flag`**: this is a known dead end; if a flag aborts with this error, stop retrying it and use an alternative like `--trace-turbo-graph` (which produces JSON) or behavioral tests.
- **Re-testing the same string constructor (`f3("")`) and the same `Cons("", X)` match behavior many times and getting the same flat result**: before running another identical test, re-read the `FactoryBase::NewConsString` code (it has a `left_length == 0` shortcut) and reformulate the hypothesis about how to defeat it.
- **Spending dozens of steps on the `IsReadOnly` flag mechanism**: if a flag is rejected, move on to a different observation tool instead of auditing `flags.cc` to understand why.
- **Repeatedly confirming a single caller of `RegExpExecInternal2` without acting on that fact**: once a unique call site is found, immediately switch to analyzing the surrounding caller logic rather than re-verifying.
- **Manually testing the same function shape (loop vs try/catch vs closure) to get tier-up**: if the goal is to reach a specific interpreter path, write an automated fuzzing loop over many shapes, rather than editing and re-running a single script.

## Missed signals
