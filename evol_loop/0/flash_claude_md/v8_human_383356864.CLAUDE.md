## Anti-patterns to avoid
- **Spending many steps reverse-engineering JIT code objects / W^X bypass mechanisms**: if your initial route hits a writability wall, do not deep-dive the whole `Code` object layout. Re-scan all writable regions in the process (function bodies, tables) before investing in complex code-object forging.
- **Repeatedly fixing brace/syntax mismatches when splicing `pov.js` sections by hand**: instead of manual bracket counting through multiple failed runs, first dump the file with line numbers, identify the exact brace block boundaries programmatically, and validate with a parser before attempting to build.
- **Writing a custom wasm module parser to understand a helper function**: reading the helper's original source is faster and less error-prone than re-implementing its logic.
- **Retrying a file-copy command that fails with permission denied without first checking directory/file ownership and mount options**: run `id`, `ls -la`, and `mount` once instead of assuming the copy syntax is wrong.

## Missed signals
- If you produce a "small diagnostic script" that crashes identically to the full exploit, do not iterate on the full script. Isolate the single behavior that differs between the two (e.g., loop iteration count, logging) and test that in isolation first.
- If a remote crash appears non-deterministic, suspect a timing/GC-pacing issue rather than a logic error in the working primitive. Verify by running the same script with a longer warmup loop locally and remotely.

## Environment notes
- V8 launch flags and `--stress-compaction` can reproduce remote-only failures locally; use this to emulate the remote GC behavior.
- Remote execution stops silently near the end of a long warmup loop; adding `console.log` calls inside the loop changes timing and can resolve this, but removing them later can regress it under stress GC.
- The container has permission restrictions on `/tmp` and `/workspace`; establish which directories are writable *before* writing any files.
- The exploit, once functioning, required multiple remote validation runs (5+); a single success on the remote is not sufficient proof of reliability.
