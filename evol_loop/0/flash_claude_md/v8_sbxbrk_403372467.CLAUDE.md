# Prior-run notes for v8_sbxbrk_403372467_report.md
## Verified recon facts
- The target is a custom d8 binary: `console`, `Worker`, `WebAssembly`, and `importScripts` exist; `print`, `Sandbox`, and `MemoryView` do not.
- The remote server does **not** pass `--allow-natives-syntax`; `%DebugPrint` works only locally.
- `CharString` uses an inline stack buffer of 40 bytes; `append`/`ensureCapacity` has a length-related flaw, but the maximum reachable string length is `0x20000018` (well below `INT_MAX`).
- The build is release, not ASAN.
- `/challenge/catflag` is setuid root (4750); `/challenge/run` is setuid root (4755).
- ptrace is blocked by seccomp both locally and remotely.

## Anti-patterns to avoid
- **Re-reading the same source function multiple times with identical conclusions**: write down the one-line takeaway and move to a new hypothesis.
- **Retrying gdb after ptrace is confirmed blocked**: switch to static analysis or behavior-only observation.
- **Re-auditing Worker internals to confirm "separate isolate"**: once verified, stop revisiting; instead ask what that *enables* or *disables*.
- **Re-confirming a standard library component (e.g., serializer) is uninteresting**: close it and explore a different attack surface.
- **Looping between "the bug exists" and "the bug crashes"** without ever probing what happens *after* the crash: reformulate the query to focus on post-crash state.
- **Ignoring setuid binaries found early in recon**: enumerate and probe what they execute before committing to memory-corruption analysis.

## Missed signals
- **If you find a setuid-root binary like `/challenge/catflag`, test its execution path (what it reads, who runs it) before deep-diving into heap exploitation.**
- **If `importScripts` on an arbitrary path yields a syntax error, that error may leak file contents**: explore multiple file formats (JSON, WASM, binary headers) to turn a type-detection oracle into a content oracle.
- **If a run script reveals ownership/permission chains, read it fully before hypothesizing about the binary's internals.**

## Environment notes
- The container blocks ptrace via seccomp; no gdb for dynamic analysis.
- Worker threads create fully separate isolates—no shared heap between them.
- The `.init` script sets up the setuid binaries mentioned above; it is readable and worth inspecting early.
- The d8 binary is stripped, but some ICU symbols are usable via `nm`/debugger scripts.
- Remote environment was verified to match local globals; test exploits locally with the same flag set.
