## Anti-patterns to avoid
- **Repeatedly probing `Sandbox`/`--expose-memory-corruption-api` after confirming it's unavailable**: once the binary grep shows no `MemoryView` string, finalize that conclusion and switch to finding other primitives.
- **Deep-diving into `JsonStringifier` internals (`AppendChars`, `CurrentPartCanFit`, etc.)**: the blocker is how to create an overly long string, not stringifier behavior; stop after understanding the OOB write condition.
- **Re-reading the same source regions or `reproduced_output.txt`**: if it yields no new info on a second read, treat the content as known and move to a new area.
- **Repeatedly auditing the `d8.serializer` path as "standard, no bug"**: the standard implementation can still be an attack surface under a UAF; only re-audit when a new corruption hypothesis exists.
- **Hard-retrying GitHub API after rate-limit (HTTP 403/rate-limit error)**: switch immediately to the googlesource mirror instead of pacing retries.
- **Downloading very large commit logs (5+ MB) in one go**: fetch streams or paginate incrementally, and process each chunk for candidate fixes before fetching the next.
- **Spending excessive steps enumerating all upstream fix commits (`10,579` commits)**: impose a hard cap on this search and force convergence on the single most promising candidate (e.g., known Atomics-related bug) once a "purely JS reachable" bug is named.
