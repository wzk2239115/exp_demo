## Anti-patterns to avoid
- **Boot-message flooding obscures command output**: Use a simple, isolated echo marker and read only the tail; do not re-run the same multi-command script to guess output.
- **`unshare -Ur -m` mount or `mknod` attempts time out or return EPERM with no usable output**: Stop retrying the same command; run one minimal probe at a time and confirm the failure signal, then pivot.
- **Repeatedly searching online for a fix commit from syzbot**: If you already have a source-level model of the bug, skip patch hunting; those results are merge commits and only waste steps.
- **Trying to compile inside the sandbox**: On any missing `ld` or toolchain error, immediately switch to local static compilation and transfer the binary over the network.
- **Long shell-command concatenations cause truncated output and heredoc failures**: Replace them with a single compiled C probe that writes results to a file, which you read in chunks.
- **Reading the same downloaded or generated output file only in one pass**: If output is long, deliberately read it in segments (with offsets) before spawning new searches or commands.
- **Repeatedly re-testing an unmodified interaction script when the previous attempt produced only a prompt**: Verify connectivity first, then read the captured output file before trying again.
