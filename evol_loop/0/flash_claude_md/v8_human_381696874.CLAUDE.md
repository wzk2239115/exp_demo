## Anti-patterns to avoid
- **Reading the same `sandboxed-pointer-inl.h` or `kSandboxedPointerShift` docs 3+ times**: after two failed source lookups, stop grepping and verify behavior with a live write-back test instead.
- **Stitching JS files with `cat`/`sed` and getting "u32 is not defined" / "no collision"**: when a combined script errors, immediately diff the source and builder files; don't re-spawn searches for the missing symbol.
- **Spending >10 steps on `setsid`/`timeout`/mailbox tricks to keep a probe alive**: if the process dies with `Terminated` and no output, switch to writing results to a file from within the probe, then read that file post-mortem.
- **Chasing GC-moved object addresses after reallocation**: if a probe's addresses go stale mid-run, re-dump the layout from the live process rather than debugging the stale snapshot.
- **Re-confirming the same conclusion (e.g., "non-sandbox uses raw pointers") multiple times**: when a source audit and an empirical test agree, close that direction permanently.
## Missed signals
- If a probe crashes at `+0x24` on read but write silently no-ops at `+0x28`/`+0x90`, treat that as a hint that **multiple fields must be co-modified**, not a validation failure. Investigate the field inter-dependency before descoping it.
- If you observe on-heap vs external buffer write-offset differences, stop and analyze the on-heap representation immediately; it may be the key to a clean arbitrary write.
- If a probe outputs your marker (`0x11111111`/`DEADBEEF`) at an address you didn't set, check whether that address is a *different object's overwritten field* before writing another probe.
