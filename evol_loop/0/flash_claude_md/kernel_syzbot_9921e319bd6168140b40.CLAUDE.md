## Anti-patterns to avoid
- **Repeatedly re-enumerating the identical sandbox env (6+ times)**: after 2 identical confirmations of a blocking fact (e.g., no /dev/fuse, mknod refused, mount fails), stop that direction and generate a new hypothesis; do not re-run the same enumeration commands.
- **Re-verifying the same privileged check 3+ times**: if source and disassembly agree twice that an ioctl requires init-userns capabilities, stop auditing that path and pivot to other attack surfaces.
- **Assuming a fix commit's described behavior matches this exact kernel**: when the patch you fetch doesn't match local source/disassembly on a claimed step, suspect a version mismatch and either compare adjacent versions or drop that assumption—do not keep confirming the mismatch.
- **Probing a listening port once and moving on**: a single timeout on port 0x4001 was treated as a dead-end; instead, sweep with varied timeouts/connections before abandoning a network surface.
- **Treating a server crash log as a progress signal**: a crashing remote VM is not a success indicator; distinguish boot-panic output from exploit-triggered behavior before spending steps to restart/re-enumerate.

## Missed signals
- **If `/bin/su` is setuid-root (observed) but you are in a nested userns**: don't conclude it's useless because `capable()` checks init userns; file-owner checks against the superblock's userns may behave differently—test file-level privilege escalation before dismissing it.
- **If you find a mounted, writable `/proc` while other mounts fail**: explore what `/proc` exposes (e.g., `/proc/1/root` traversal) instead of assuming all userns paths are blocked; the `mount_too_revealing` rule that blocks sysfs may not apply to the already-mounted proc.
- **If you see a PID namespace where the jail shares NSpid with fewer entries than expected**: read `/proc/1/root/...` for host filesystem visibility; this was obtained but never acted on.
- **If a downloaded syzbot/fix description arrives before you've read the local repro.c**: read the local file first—the download may describe a different build than the one you're attacking.
