## Anti-patterns to avoid
- **Repeatedly trying to paginate gitiles commit logs with wrong query syntax**: after 2 failed attempts, fetch the regress test file from the fix commit instead of re-querying the API.
- **Spending 100+ steps auditing every wasm type-path when flags disable them**: if a feature is behind a flag test, confirm flag presence in `--help` early; consider the flag-gated list "dead" and switch to fuzzing/parameterized testing.
- **Attempting gdb/strace/ptrace in the sandbox**: if `ptrace: Operation not permitted` appears, switch immediately to d8-level instrumentation (e.g., `--abort-on-uncaught-exception` or custom signal handling) rather than trying alternate ptrace methods.
- **Re-verifying the same 1M-type boundary multiple times**: once you've seen N=999,995 OK and N=999,996 OOM in both local and remote, stop re-testing; move on to other paths.
- **Getting stuck re-reading assembler/Zone allocation code without a concrete memory-corruption target**: after confirming a label-link bug, plan the next primitive (e.g., what data to overwrite) before deep-diving again.

## Missed signals
- If you find a single-N SEGV whose address ends in a suspicious hex pattern (e.g., `...5da0f8`), check whether that address correlates with a known heap spray or an RTT array index, then test overwriting that region from JS, not just the wasm module.
- If a crash only occurs on the signature-mismatch path (same-signature compiles fine), immediately try to craft a fake-but-valid signature that triggers the mismatch while keeping the OOL stub reachable, instead of merely confirming the path.
- If you find code stating a FAR jump targets `2*P+6`, verify if that value is writable from a JS array or wasm memory; if yes, prioritize building a read/write from it rather than chasing further compiler internals.
