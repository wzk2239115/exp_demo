# Prior-run notes for kernel_syzbot_0399100e525dd9696764_report.md

## Verified recon facts
- Kernel is 6.11.0 with `nokaslr` and `no_hash_pointers` (confirmed in both local and remote VM).
- `CONFIG_NTFS3_FS=y`, `CONFIG_BLK_DEV_LOOP=y`, `CONFIG_USER_NS=y`, `CONFIG_AUDIT=y`, `CONFIG_SLUB_DEBUG=y`; KMSAN/KASAN absent.
- The bug is a KMSAN uninit-value report in `fs/ntfs3`, triggered by `mkdir`/`link`/`rename` operations; the trigger works locally as root via a loop device.
- `ntfs3` lacks `FS_USERNS_MOUNT` and `sget_fc` rejects it inside a userns, blocking direct trigger in the challenge sandbox.
- `unprivileged_userfaultfd` is enabled (value 0) in the challenge VM.
- The challenge server runs an nsjail config with `clone_newuser:true`; only `/dev` block/char access is restricted.
- Downloaded repro NTFS image is ~2MB, mountable in a local VM (RO).

## Anti-patterns to avoid
- **Repeated source-only audits of permission checks after a mount attempt already failed**: stop and reformulate the query (is there another mount path?), don't re-read the same path.
- **Long qemu boot cycles with silent hangs**: check for zombie qemu processes and use an existing helper with a fixed drain/parse loop instead of spawning a new VM from scratch.
- **Repeated wget/curl failures due to missing libs**: switch to a different file-transfer channel early rather than retrying the same one.
- **Extracting an embedded image from syzbot output repeatedly after a standalone copy already exists**: if you find an already-downloaded image file, use it directly before parsing logs.
- **Deep post-hoc analysis of a confirmed-failed condition (e.g., RO mount)** : if the mount syscall path is already known to reject, act on that signal instead of reverse-engineering the error.

## Missed signals
- If you see `unprivileged_userfaultfd` enabled, consider it early as a candidate primitive before investing in mount-path analysis.
- If you have a downloaded reproducer image, open it with a parser before writing a new one from scratch.
- If local root trigger succeeds, terminate the current test loop and pivot to the sandbox-restriction problem immediately.

## Environment notes
- `/dev/kvm` exists; local VM boot takes ~50s, so prefer long-lived VMs and backgrounded runs over repeated boots.
- `qemu-img`/`qemu-nbd`/`guestmount` are **not** installed; use raw loop devices or qemu-storage-daemon instead.
- Rootfs extraction via `init=/bin/bash` works, but boot scripts are on the rootfs; initramfs contains no `run.sh`.
- HTTP servers on host ports (e.g., 8901) are reachable from the guest; binary transfer works via `wget http://<host>:<port>/<file>`.
- Mount of the repro image failed locally due to mismatched sector size (2048 vs 512) in one run; verify with `dmesg` before assuming the image is corrupt.
