## Anti-patterns to avoid
- **`--trace-turbo` yields no files, but you retry with variants anyway**: first diagnose *why* the filter/compile path blocks output (e.g., check `trace-turbo-filter` semantics and whom it dumps) before spawning another run.
- **`--trace-representation` errors as readonly/exists, and you keep probing it**: verify build-time flag enablement (`v8_enable_slow_tracing`) before assuming the flag is available.
- **GDB fails with ptrace errors or exit 127, but you keep adjusting scripts**: once seccomp ptrace denial is confirmed, abandon dynamic debugging entirely; do not burn steps on workarounds.
- **Static type diff between typer phases shows 0 changes, and you rerun on new graphs**: transient types won't surface in final graph JSON; stop this loop and seek an observable runtime side effect.
- **Fetching remote commit test files when the fix commit has no test**: check local source/commit metadata first to avoid rate-limited fruitless downloads.
## Missed signals
- If you find the IIFE *is* TurboFan-OSR-compiled but output values stay NaN, treat that as "type error occurred but is invisible in graph JSON" — pivot to placing a detectable side effect (array length, object shape) inside that compiled function.
- If you confirm the source revision is vulnerable, don't block entirely on a debug build; in parallel, construct PoCs that expose the wrong type through observable behavior rather than graph dumps.
