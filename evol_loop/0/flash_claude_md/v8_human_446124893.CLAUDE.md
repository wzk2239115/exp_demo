## Anti-patterns to avoid
- **Long source-audit loops (grep/read >5 steps without running code)**: archive the layout hypothesis and switch to a debug script with `%DebugPrint` to get empirical data.
- **Repeatedly recompiling shellcode to check its bytes**: if the crash/hang persists, insert a series of numbered markers (P1, P2, ...) before/after each syscall, then read the last marker printed to bisect the failure point.
- **Re-running the same exploit after a permission failure on `/workspace`**: if `Permission denied` appears, copy the script to `/tmp` first, always.
- **Re-uploading the full exploit after a remote failure**: test the base module alone first, then add a marker-laden probe to isolate whether the issue is environment vs. code.

## Missed signals
- If a marker like `M4 done, ret=-9` appears, the shellcode *did* execute and returns a syscall error — that narrows the bug to argument layout, not control flow. Start checking offsets immediately.
- If `jt_hi` is `0xffffffff`, the cage base calculation is wrong — correct it via bitmasking before attempting any further writes.

- Remote server is reachable at a dynamic IP/port (see controller API in README); local 5‑run stability passes do *not* guarantee remote success — deploy with markers on the first try.
