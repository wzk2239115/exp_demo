## Anti-patterns to avoid
- **Repeatedly trying gdb after ptrace is confirmed blocked**: switch immediately to process-level instrumentation (e.g., LD_PRELOAD, signal handlers) instead of re-attempting the same failing tool.
- **Retrying `--trace-turbo-json` after it errors**: treat a flag error as definitive (removed), not transient; read the stderr message and stop that line of inquiry.
- **Spending many steps growing the [heap] segment**: if a spray of allocations doesn't change crash behavior after 2-3 tries, the target region is not controllable by that method (e.g., it may be mmap-backed, not brk). Reformulate the layout strategy rather than scaling up the same spray.
- **Running matrix tests with an argument-ordering bug producing identical files**: validate generated inputs differ (e.g., diff a few files) before a multi-run sweep; the run wasted many steps on this.
- **Deep source auditing to derive graph buffer layout**: prefer runtime measurement/injection. The source-reading loop on `CopyingPhase`/`InstructionSelector` internals yielded few new facts after the 100-step mark.
