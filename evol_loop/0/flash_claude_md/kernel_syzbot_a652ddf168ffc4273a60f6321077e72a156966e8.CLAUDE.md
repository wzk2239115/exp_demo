## Anti-patterns to avoid
- **Re-verifying the same already-confirmed patch repeatedly (disasm/probe cycles)**: after the first confirmation, commit to that conclusion and switch to looking for the next primitive.
- **Fragmented environment recon via many tiny vm_env*.py scripts**: each yields a sliver; instead write one comprehensive probe that dumps namespaces, mounts, caps, devices, and config in a single run.
- **Hunting zombie QEMU `<defunct>` processes as if they were harmful**: they are normal; ignore and push on.
- **Re-running a mount test after EPERM to "be sure"**: read the source flag that blocks it and reformulate, don't re-execute the same failure.
- **Garbled VM output flooding the socket buffer**: if probe output is truncated, add explicit sync/delimiters rather than rerunning blind.
## Missed signals
- If you see `CONFIG_INIT_ON_ALLOC_DEFAULT_ON=y`, act on it: reason immediately about what uninitialized-memory leaks this kills before designing around them.
- If you find a full caps userns, verify which filesystem types carry `FS_USERNS_MOUNT` (e.g., FUSE) before spending effort on one that doesn't.
- If `/proc/modules` prints empty, treat it as a signal about module visibility constraints, not as an anomaly to re-check.
