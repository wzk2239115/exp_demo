# Prior-run notes for v8_human_398065918_report.md

## Verified recon facts
- The challenge binary is a V8 d8 build; it likely enables pointer compression (x64 default) and V8_ENABLE_SANDBOX, but not V8_ENABLE_SANDBOXED_EXTERNAL_POINTER_TABLE.
- `%DebugPrint` and `%GetOptimizationStatus` work in local builds; `%GetHeapStatistics` may not be defined even with `--allow-natives-syntax`.
- Status bit encoding verified locally: bit5=maglev (value 49), bit6=turbofan (value 81). In a natural run the target function skipped maglev and went straight to turbofan.
- `--trace-maglev` is not a recognized flag in this build; `--print-maglev-graph` was available. `--print-code`-family flags are also not recognized.
- WebAssembly is available server-side; most d8 shell functions are removed by the patch.
- Server does not pass `--allow-natives-syntax` or `--predictable` (confirmed via Math.random variance between runs).

## Anti-patterns to avoid
- **Sweeping many `n` values repeatedly after concluding the target flag is absent**: once you have a verified precondition not met remotely, set a hard stop (e.g., 5 more experiments) before spending hundreds of steps on that axis.
- **Parallel sweeps sharing temp files**: results were false positives from file races; if a hit cannot be reproduced with unique temp files, treat it as spurious and don't chase it.
- **Retrying gdb after seccomp ptrace denial**: the environment blocks ptrace; do not re-attempt debugger routes after the first explicit failure.
- **Rebuilding brute scripts from scratch after helper/import/file-extension errors**: read the existing downloaded/generated file before spawning a new search or rewrite; several steps were lost to confusing a Python file saved as `.js`.
- **Letting `console.log` flood output during background sweeps**: status lines drowned out the DebugPrint signals you actually needed; route debug output to a dedicated file.
- **Changing the detection code to avoid a crash**: the trigger is extremely body-sensitive (e.g., adding a `var saved;` or altering a `toString` call changes whether the bug fires); when a mutation kills the crash, revert that mutation rather than "fixing" it.

## Missed signals
- If you find a variant that corrupts memory but does not crash locally under your full flag set, test that exact body shape remotely before deepening the local sweep — it was the closest thing to a usable primitive and was left unexplored server-side.
- If a run with `--predictable` plus a custom random seed produces no output (possible crash), that indicates seed-dependence of the trigger; vary the seed in small increments before concluding the trigger is gone.
- If you confirm a function jumps straight to turbofan under natural conditions, act on that tier-skip signal (adjust warmup to hold the maglev tier) instead of continuing the same trigger sweep.

## Environment notes
- The remote host is heavily loaded (load avg >50), so wall-clock timeouts are meaningless; check CPU time before trusting a sweep's "crash".
- Rootfs extraction and local VM boot worked; the d8 binary requires its `snapshot_blob.bin` in the expected location or it fails early.
- Seccomp filter mode 2 blocks ptrace entirely; plan on source-reading and output-based probing as your only debugging tools.
- The local d8 build and the remote may differ in flags or patch state; assume any "works locally" result must be re-verified remotely.
