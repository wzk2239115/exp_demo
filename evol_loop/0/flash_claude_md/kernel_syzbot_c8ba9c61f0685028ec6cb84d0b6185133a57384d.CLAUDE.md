## Anti-patterns to avoid
- **Repeatedly hunting for a fix patch across web sources (301/404/rate-limit spam)**: if the patch isn't in the first two sources, compare the buggy function's source against the newest upstream kernel instead — faster and reliable.
- **Trying to get interactive serial via socat/nohup/zombie processes for the VM**: wrap the QEMU invocation in a single self-contained script ending with socat to the socket; avoid background/nohup chains that die silently.
- **Iterating after every kernel panic when VM restarts**: the rootfs is read-only and requires remounting tmpfs plus reconfiguring every boot; batch your experiments so one boot tests multiple hypotheses.
- **Analyzing device features by hand from dumps**: use a script to decode `NETIF_F_*` bit positions programmatically — manual bit math produced repeated errors.
- **Spawning yet another file-transfer attempt before checking the HTTP server was actually serving the intended directory/port**: a stale server caused confusing 404s; always verify the serving path first.

- `/tmp`, `/proc`, `/sys` are not writable/mounted by default — remount or mount tmpfs via the serial once booted; consider baking these mounts into your boot script.
- `ip` is broken (missing dynamic library); `ifconfig` and `/sbin/ip` may work but check. Preset network interfaces appear on boot (bridge0, dummy0, veths).
