- `turboshaft_wasm` flag defaults to **false**; only enabled via `--turboshaft-wasm` or `--future`. Without it, wasm GC code compiles via classic Turbofan/Liftoff, not Turboshaft.

- Server d8 is hardened: no `print`, `read`, `write`, `quit`, `Realm`, or `os`; `WebAssembly` and `Worker` are available; `%`-prefixed intrinsics are stripped.

## Anti-patterns to avoid
- **Repeatedly building trigger modules after confirming the vulnerable pipeline is off**: the server cannot enable Turboshaft; stop and re-examine the attack surface (e.g., other compilers, wasm features, retained APIs) rather than refining module bytes.
- **Hunting for upstream fix commits across Gitiles/Gerrit/GitHub/Codesearch when endpoints 403/404/rate-limit**: if two attempts fail, switch to reading the local source tree diff directly — the vulnerable pattern already exists locally.
- **Trying to pass `ref null none` values from JS into wasm**: the type system rejects it; construct everything inside wasm or abandon that angle immediately.
- **Writing a custom wasm builder/disassembler from scratch when the POC already contains valid bytes**: extract and reuse the POC's structure before reimplementing encoders; the disassembler repeatedly misparsed LEB and packed types, wasting cycles.
- **Investigating `experimental_wasm_inlining` flag definitions**: compilation succeeds without it; it is unrelated to the failure — if the flag seems missing from definitions, move on rather than tracing generated macros.

## Missed signals
