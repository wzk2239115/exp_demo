## Anti-patterns to avoid
- **Repeated `ninja` status checks that only confirm "still building"**: treat a build as a black box; poll once after a generous timeout, and always verify the output binary is newer than your last source edit before trusting it.
- **Deep source-grepping for missing opcode constants**: when a builder API rejects a name, first check the file's own opcode table or a working example call before spawning a search loop.
- **Debugging a wasm validator error with extensive source reading**: encode a minimal reproduction with a print/error trace first; the root cause may be trivial (e.g., operand order) and show up in one test run.
- **Re-running geometry experiments without verifying the test script itself**: if the same entry index fails across varying table counts, suspect a bug in your wasm body builder, not the exploit layout.
- **Assuming a background build succeeded silently**: after a build command, immediately check for a command-not-found or exit code before launching further dependent steps.
