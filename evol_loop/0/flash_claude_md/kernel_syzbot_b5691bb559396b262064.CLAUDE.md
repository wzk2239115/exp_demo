## Anti-patterns to avoid
- **Repeating a failing compile command with minor variations**: after one failure, pause and inspect what resolution-dependent tool is missing; a single flag change (`-B/usr/bin/`) unblocked it after many redundant attempts.
- **Retrying a remote command whose output is garbled or truncated**: stop and fix the harness (e.g., shell echo interference) before iterating; don't assume the run itself failed.
- **Endless byte-pattern gadget searches**: if your search pattern returns "none" repeatedly, stop and re-derive the actual constraint (e.g., relocation semantics) before launching another variant.
- **Fully reading a long reference exploit again in the middle of porting**: extract the required offsets and the dependency list once, up front, and go back only for a specific unresolved line.
- **Spending many steps on permission bypass attempts after a hard check is identified**: once a capability check runs against the init namespace, branch to re-scoping the attack surface rather than exhausting local tricks.
## Missed signals
- When a reference exploit's check mode confirms "VULNERABLE", immediately compute whether the new kernel's available ROP constraints (e.g., max payload size) can fit the required chain **before** deep-diving into gadget archaeology.
- A "step1 failed" with a specific errno (e.g., -34/ERANGE) should be traced to a size limit in the API **immediately**; the root cause may invalidate an assumption you're about to spend hours optimizing around.
