- Build has `v8_enable_sandbox=false`, `dcheck_always_on=false`; Maglev is the optimizing compiler in use.
- The bug triggers specifically when `Math.sqrt(0)` folds to constant 0.0 during Maglev compilation; non-zero constants like `sqrt(2)` do NOT trigger. `sqrt(1)` gets Smi-tagged, also benign.
- A stale reference to a freed HeapNumber slot can be produced after a simulated or pressure-induced new-space GC; the freed slot is reclaimed by a subsequently allocated object.
- Allocator slot behavior verified: a fresh `new Array(0)` consumes 5 slots (not 1); `new Object()` and String allocations consume different counts. Pre-warming does not change slot counts.
- After GC, `v0` may still point to a slot now holding `AllocationMemento` or another object; a forced `%SimulateNewspaceFull()` (when natives allowed) makes the stale slot deterministic.

## Anti-patterns to avoid
- **Repeatedly trying different pad types (String/Object/Array) while `v0===victim` stays false**: the root cause is GC timing or slot-consumption mismatch, not the pad type. Fix one variable at a time — pin the GC trigger, then vary the allocator.
- **Testing `v0` for equality or printing it to verify aliasing**: runtime type checks force ToNumber/ToString coercion, so reading `v0` yields a string or crashes instead of raw bytes. Use a structure whose fields are read as tagged values, not a number-typed variable.
- **Deep-diving `CanElideWriteBarrier` type-inference code for 7+ steps**: understanding the mechanism is good, but does not accelerate exploitation. Stop once you have enough to write a trigger.
- **Assuming a single reclaimed slot gives you both type confusion and a read/write primitive**: only one slot is freed per trigger — plan an attack with exactly one aliased object.
- **Spawning a new search for each failed assertion**: if the same comparison fails three times in a row, stop and reformulate the verification method (e.g., use DebugPrint of the object graph rather than JS equality).
- **Allocating large pressure arrays inside the trigger function before the stale slot is made**: this prematurely frees or corrupts the HeapNumber, causing crashes during subsequent reads.

## Missed signals
